## 2026-07-05 - [PII exposure and lack of individual GET endpoints in backend]
**Vulnerability:** The database endpoint `/api/db` was exposing the raw JSON containing sensitive customer fields (`users` and `orders`), leaking unmasked personal identifiable information (PII) like customer names and email addresses. Additionally, the backend was missing individual sanitizing GET endpoints for categories, pages, and orders, which forced the client-side to request potentially unsafe/unfiltered data.
**Learning:** Returning a complete or unfiltered local JSON database dump directly via an API shortcut creates severe information disclosure vectors. Even when the front-end only renders specific non-sensitive elements, the raw network payloads remain exposed to any user querying the server endpoints.
**Prevention:** Always filter out collections containing sensitive records or PII (such as `users` or `orders` structures) on the server side before serializing JSON objects to endpoints. For public lists such as orders history or logs, map over records and apply masking or hashing functions to PII properties (e.g., masking emails into `ab***@domain.com` and names into `J*** d***`) prior to returning them.
