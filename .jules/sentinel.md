## 2026-07-06 - [Sanitization of Unified Database Endpoints and Server Hardening]
**Vulnerability:** Information Disclosure and Lack of Server Hardening. The `/api/db` endpoint was returning the entire database object, including sensitive `users` and `orders` collections, which could lead to PII exposure. Additionally, the Express server lacked standard security headers and disclosed its technology stack via the `X-Powered-By` header.
**Learning:** Unified endpoints that serve initial state for SPAs are convenient but dangerous if they consume a raw database object without filtering. Security headers are a simple but effective defense-in-depth measure that should be configured by default.
**Prevention:** Always use destructuring or a dedicated sanitization function to whitelist properties when returning database objects to the client. Use `app.disable('x-powered-by')` and set standard security headers (`X-Content-Type-Options`, `X-Frame-Options`) in every Express application.
